## Пространства и API

Вместо неработающего select — компактное доступное меню: текущий выбор,
«Создать пространство», «Управление пространствами». Поддержаны создание,
переименование, переключение, длинные названия, стрелки/Home/End и Escape.
Используется существующий AnchoredPopover и модальные окна приложения.
Меню отображает реальные пространства; «Работа», «Дом», «Личное» не создаются
автоматически. Управление не содержит опасного удаления пространств.

| Метод | Назначение |
| --- | --- |
| GET `/api/workspaces` | `{workspaces:[{id,name,is_default}]}` |
| POST `/api/workspaces` | Создать по `{name}`; HTTP 201 |
| PATCH `/api/workspaces/{id}` | Переименовать по `{name}` |
| POST `/api/events`, `/api/message` | `workspace_id` в JSON |
| GET `/api/events`, `/api/search`, `/api/history` | `workspace_id` в query |
| PATCH/DELETE `/api/events/{id}` | `workspace_id` в query |
| PATCH `/api/events/{id}/color` | `workspace_id` в query |

Название обрезается по краям, допустимо 1–80 символов. Пустые названия
не принимаются. Дубликаты сравниваются без регистра, включая кириллицу.
Неизвестный workspace даёт 404, отрицательный/нулевой ID в контекстных полях
отклоняется валидацией. Неверный workspace при PATCH/DELETE/цвете записи
даёт 404 и не меняет её. Все значения передаются в SQL параметрами.

Без workspace_id используется ID=1. Это обычное существующее пространство,
а не режим «показать все». Выбранный ID хранится в localStorage и проверяется
по списку доступных пространств при загрузке. Он передаётся явно в запросах;
глобального mutable active_workspace на сервере нет.

## Данные и миграция

Транзакционная миграция SQLite v2→v3 создаёт `workspaces`, единственное
начальное «Общее пространство», колонку `events.workspace_id NOT NULL DEFAULT 1`
и индекс по workspace/date/status. Существующие строки получают default=1,
без изменения ID, названий, дат, цветов, истории и без дублирования.
Старые Event DTO остаются совместимыми с общим контрактом.

Storage использует ContextVar для request-local workspace. Списки, чтение
по ID, изменения, удаление, дубликаты и конфликты встреч учитывают контекст.
Поиск и календарь получают уже разделённые сервером данные. Это не только
frontend-фильтр. «Мой день» и счётчики производятся из той же коллекции.
Общие настройки цветов остаются общими для профиля; цвет отдельной записи
проверяется через её workspace.

Проверки использовали временные базы. `data/ritm.db` и пользовательский CSV
не открывались для записи. Для пользовательского preview перед обновлением
сделан согласованный SQLite-backup:

## Ассистент и гонки

Авторитетный контекст передаётся в запросе. Публичный session_id при смене
пространства не меняется; сервер разделяет внутренние ключи истории и pending
состояния по workspace. Для пространства 1 сохранены прежние ключи, поэтому
старая история и незавершённые подтверждения доступны.
Идемпотентные ответы дополнительно привязаны к workspace: тот же request_id
в другом пространстве возвращает 409, не чужую запись. Формат fingerprint
старых запросов создания сохранён для совместимости повторов.

При активном AI-запросе, записи голоса или изменении данных переключение
блокируется до завершения. При несохранённой форме действует существующее
подтверждение закрытия. Pending-подтверждение без активного запроса не мешает
смене пространства: оно восстановится при возвращении в своё пространство.
Черновики сообщений разделены в памяти, ошибки повторной отправки — отдельными
ключами sessionStorage. История перезагружается для выбранного контекста.

При быстром переключении коллекция и выбранная запись очищаются сразу,
поиск отменяется. Ответ старого GET не применяется к новому пространству;
после него подгружается актуальная коллекция. Ответ AI также проверяется
по captured workspace/session перед отображением.

## Ограничения и решения для Claude

В исходном приложении нет авторизации, таблицы users и user_id. Реализованы
пространства **одного локального профиля**. Это не многопользовательская
изоляция: для backend с авторизацией Claude должен согласовать владельца
workspace и проверку текущего пользователя. Фиктивная регистрация не добавлялась.
Удаление/архивирование и перенос записей между пространствами не входят в эту правку.
Выбор активного workspace восстанавливается в том же браузере, не синхронизируется
между устройствами. Проверен Chromium; мобильная версия не разрабатывалась.

Preview доступен на `http://127.0.0.1:8765`, оставлен по поручению пользователя
тестировать локально. Тестовый 8766 использует временную базу и останавливается.
