# Контекстные элементы и управляемое создание в чате

Отчёт по требованиям и изображениям пользователя от 30 октября 2026 года.

## 1. Что найдено в проекте

Рабочий стек — статические ES modules, CSS, FastAPI, SQLite. Отдельной сборки,
React и Next.js нет. Панели и представления управляются `dashboard.js`, история
и голос — `app.js`, общие данные — EventStore. Существующие формы, цвета и
сворачивание панелей сохранены и проверены повторно. Рабочая база не использовалась
в тестах; сервер проверки работает с временной базой и фиксированными часами.

## 2. Подтверждённые проблемы

- Браузерные select/date/time открывали системные меню, отличающиеся от интерфейса.
- Контекстные компоненты имели разные правила позиционирования и радиусы.
- Нижние команды и ввод конкурировали с историей за высоту панели.
- Обычная команда создания сразу записывала сущность; отдельной карточки проверки не было.
- Подтверждения конфликтов имели общие короткие варианты «Да/Нет».
- Несохранённые изменения закрывались через системный `window.confirm`.

Отказ сохранения цветов не воспроизведён: серверная запись и наследование работают.
Проверены сброс, индивидуальный цвет, произвольный HEX и перезагрузка.

## 3. Что исправлено

Все списки типов, фильтров, сортировки и статуса используют собственные меню.
Дата открывает календарь с сеткой Пн–Вс, текущим/выбранным днём, переключением
месяца/года, навигацией по дням с клавиатуры, «Сегодня» и «Удалить».
Время выбирается отдельными колонками часов и минут; точное значение вне шага
пять минут сохраняется при открытии. Ручной ввод в поля тоже доступен.

Панели находятся в верхнем слое браузера, позиционируются относительно поля,
ограничены окном и не обрезаются модальным диалогом. Поддерживаются Escape,
закрытие вне панели, возврат фокуса, пересчёт при изменении размера и прокрутке.

## 5. Реальные backend-контракты

Используются существующие `/api/message`, `/api/history`, `/api/events`, поиск,
PATCH/DELETE записей и методы цветов. В `MessageIn` добавлен опциональный
`require_confirmation` (по умолчанию false). Web-чат отправляет true.

```json
{
  "session_id": "current-session",
  "request_id": "unique-request-id",
  "text": "Поставь задачу проверить макет",
  "require_confirmation": true,
  "new_event_color": null
}
```

Ответ проверки содержит `kind: "confirm"`, `expecting: "confirmation"`,
`suggestions: ["Да", "Нет"]`, `proposal` с полями `event_type`, `title`, `date`,
`time`, `duration_min`, `is_deadline`, `intent`, `color`. Это ещё не Event;
он не попадает в список, календарь или «Мой день». В конфликте `events` может
содержать уже существующие пересекающиеся записи, а `proposal` — новое предложение.

Кнопки «Подтвердить»/«Отказаться» отправляют `Да`/`Нет` в той же сессии с новым ID.
Повтор после потери ответа использует исходный ID. Сервер сохраняет предложение,
его цвет и активность. История возвращает `proposal`, `active_confirmation`,
`resolution` и идентификатор запроса. Перезагрузка страницы и перезапуск сервера
не создают сущность автоматически. Явный null сбрасывает цвет; отсутствие поля
сохраняет цвет предложения. Запись и цвет фиксируются одной транзакцией.

Прямой POST из формы остаётся явным созданием; конфликт/прошедшая дата требуют
существующего подтверждения. Прежние клиенты без флага не меняют поведение.
Защищённые файлы общих контрактов и схема Event не изменены.

## 7. Команды проверки

Из корня проекта, с установленными зависимостями:

```powershell
.venv\Scripts\python -m pytest -q
npm --prefix web run typecheck
npm --prefix web run lint
npm --prefix web test
$env:AIVRITM_TEST_PYTHON = (Resolve-Path .venv\Scripts\python.exe).Path
$env:AIVRITM_TEST_PORT = '8766'
npm --prefix web run test:e2e
```

В этой среде Python взят из `%TEMP%\aivritm-frontend-venv`, Chromium — из
`%LOCALAPPDATA%\ms-playwright\chromium-1248\chrome-win64\chrome.exe`.
Путь к Chromium передаётся через `AIVRITM_BROWSER_PATH`.
Build не запускался: у статического frontend нет сборочного шага.

## 8. Проверки и артефакты

Итог: **476 pytest**, **15 Node unit**, полный прогон **58 Playwright E2E** — успешно.
TypeScript strict/checkJs, ESLint и `git diff --check` проходят.
После финальной правки прокрутки восстановленного предложения повторно прошли
4 затронутых E2E: восстановление/отказ/создание, потеря ответа подтверждения,
сворачивание AI и защита от запоздалой истории. Восстановленные кнопки дополнительно
проверяются на нахождение внутри видимой области истории.
Затем добавлено восстановление цвета при перезагрузке во время уточнения:
история возвращает `pending_color` для последнего незавершённого ответа.
Этот новый сценарий и 5 связанных E2E прошли отдельным прогоном (6/6);
20 затронутых API-тестов тоже прошли. Теперь в браузерном наборе 59 сценариев.
Проверяются реальные HTTP-запросы и значения БД, отсутствие создания до согласия,
отказ, повтор, уточнения, цвет, перезапуск сервера, формы и сохранение черновиков.
Браузер проверяет клавиатуру, Escape, геометрию и отсутствие ошибок страницы.

Размеры новой серии: 1280×800, 1366×768, 1440×900, 1536×864, 1536×960,
1920×1080. Регрессионная серия дополнительно включает 1343×868, 1536×985,
масштаб вкладки 125%, длинную историю и тысячу архивных записей.

Артефакты — `%TEMP%\aivritm-controls-qa`: `e2e-results.json` последнего
прогона шести затронутых сценариев, снимки
`custom-select-*`, `custom-calendar-*`, `custom-time-*`,
`chat-awaiting-confirmation.png`, `chat-confirmed-and-declined.png`, снимки
редактора, форм, цветов и свёрнутых панелей. Визуально просмотрены списки,
календарь и время на 1366×768, календарь на 1920×1080, предложение до
подтверждения и результат создания/отказа.

Preview перезапущен на `http://127.0.0.1:8765`; перед перезапуском создана
SQLite backup-копия его базы. После запуска проверены health, новый флаг в
OpenAPI, версии статики, сохранение 1002 существующих записей и двух
индивидуальных цветов. Новые тестовые записи в preview не создавались.

## 9. Ограничения и решения для Claude

Нет полей описания/приоритета/пространства, авторизации, внешней синхронизации,
доставки уведомлений, общего доступа и файлов. Они требуют согласования модели
и API; отдельный документ для backend — [BACKEND_REQUIREMENTS.md](BACKEND_REQUIREMENTS.md).
Цвета относятся к общему локальному профилю, пока не введены пользователи.
Мобильная версия не разрабатывалась. Проверен Chromium; другие браузеры и
реальное голосовое распознавание через микрофон этим прогоном не проверялись.
Системное предупреждение браузера при закрытии вкладки с черновиком остаётся:
его внешний вид задаёт браузер. Выбор произвольного цвета дополнительно доступен
через системную палитру, основная палитра и HEX находятся в собственном popover.
Существующий разбор свободной речи не переписан.

Для объединения нужно принять опциональное API-расширение подтверждений и
согласовать последующие бизнес-поля по документу backend. Субагенты не запускались.
