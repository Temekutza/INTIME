# Интерфейс InTime

Статический UI планировщика: задачи, встречи, напоминания, календарь, пространства и чат с ассистентом. Сборки нет — браузер грузит ES-модули. В Docker статику отдаёт nginx, `/api/` проксируется на backend.

Это не отдельное приложение на SQLite. Локальный прототип Aivritm / Windows / `uv` / `python -m ritm` к этому репозиторию не относится. Источник данных — PostgreSQL через слой `/api` FastAPI.

Как поднять весь стек, посеять данные и какие порты слушать — в корневом [README.md](../../README.md).

## Как смотреть изменения

Образ frontend копирует файлы на `docker build`. Volume исходников нет, поэтому после правок:

```bash
docker compose build frontend && docker compose up -d --no-deps frontend
```

Обычного обновления страницы после пересборки достаточно: у статики `Cache-Control: no-cache`. К `styles.css` и `dashboard.js` в `index.html` дополнительно стоит параметр `?v=…`.

Backend в контейнере монтируется с хоста и перезагружается сам; фронт — нет.

## Поведение

- Выбранное пространство (`localStorage` ключ `ritm.workspace-id`) действует на списки, поиск, историю ассистента и создание записей.
- Типы: `task`, `meeting`, `reminder`. Статусы в UI: `planned` и `done`.
- Название обязательно. У задачи дата и время необязательны. У встречи и напоминания нужны дата и время. У встречи длительность 1–1440 минут (в форме по умолчанию 60).
- Создание и изменение через чат ждут подтверждения (кнопки на карточке).
- Календарь: день, неделя, месяц, год, список. Напоминания группируются как задачи: созданные / завершённые.

Если после пересева БД экран пустой, в `localStorage` мог остаться старый id пространства.

## Модули

| Файл | Ответственность |
| --- | --- |
| `dashboard.js` | Компоновка, вкладки, поиск, пространства, часы |
| `app.js` | Чат, голос, история, подтверждения |
| `lib/api.js` | HTTP к `/api`, `workspace_id`, проверка ответов |
| `lib/store.js` | Коллекция записей и PATCH |
| `lib/model.js` | Даты, сортировка, группировка, `fieldErrors` |
| `lib/views.js` | Списки задач и напоминаний |
| `lib/calendar.js` | Сетка календаря |
| `lib/editor.js` | Редактор записи |
| `lib/create-event.js` | Форма создания |
| `lib/workspace.js` | Текущее пространство |
| `lib/colors.js` | Цвета типов и записей |
| `lib/fields.js` | Select / дата / время |

Создание: `POST /api/events`. Чат: `POST /api/message`. Список и поиск всегда с `workspace_id`.

## Проверки

Из этого каталога:

```bash
npm test
npm run typecheck
npm run lint
```

`npm test` гоняет unit-тесты Node (`model`, `store`, `workspace`, `calendar`, цвета, мат). Живой микрофон, синтез речи и платный LLM в них не входят.

Playwright-сценарии в `tests/*.spec.js` — наследие прототипа с отдельным тестовым сервером; для текущего Docker-стенда источником правды остаются unit-тесты и ручная проверка на http://127.0.0.1:3010.

Отчёты отдельных этапов (`FIXES.md`, `COLORS.md`, `WORKSPACES_REPORT.md` и другие) описывают прошлые прогоны и не заменяют корневой README.
